# Contributing to spectral-trust

Bug reports, fixes, new diagnostics and documentation improvements are all
welcome. This file covers how to set up a development copy, run the tests,
match the code style and propose a change.

## Development setup

```bash
git clone https://github.com/vcnoel/spectral-trust.git
cd spectral-trust
# optional: the CPU build of torch, as in the test workflow
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -e .
pip install pytest
```

## Running the tests

```bash
python -m pytest -q
```

The suite builds its attention matrices and signals synthetically, so it
needs no GPU, no network and no model download. The workflow in
`.github/workflows/tests.yml` runs it on Python 3.10 and 3.12 with the
Hugging Face Hub set to offline mode; you can do the same locally:

```bash
HF_HUB_OFFLINE=1 python -m pytest -q
```

One test exercises a CUDA device and is skipped when none is available.

Two groups of tests need more, and are skipped otherwise:

```bash
# the TransformerLens and nnsight adapters against run_with_spectra on gpt2
pip install -e ".[tl,nnsight]"
python -m pytest -q tests/test_interop.py

# run_with_spectra on tiny random checkpoints (downloads them)
SPECTRAL_TRUST_MODELS=all python -m pytest -q tests/test_model_matrix.py
```

`.github/workflows/models.yml` runs both. The documentation builds with
`pip install -e ".[docs]"` and `mkdocs build --strict` (`mkdocs serve` to
preview it); `.github/workflows/docs.yml` builds it on every pull request.

Please add a test with every fix and every new metric. A regression test
should fail on the code before the fix; its docstring says what was wrong.

## Code style

- PEP 8, four-space indentation, lines up to about 100 characters.
- Every source file under `src/spectral_trust/` starts with the two-line
  notice used by the existing files: the copyright line and
  `SPDX-License-Identifier: Apache-2.0`.
- Public functions have type hints and a docstring that states tensor shapes
  (for example `[heads, seq, seq]`), the normalisations it supports and what
  it returns.
- A new diagnostic declares its tensor family in `METRIC_FAMILIES`
  (`spectral.py`) or in the per-head family constants: `"attention"` if it
  reads attention weights only, `"hybrid"` if it also reads hidden states.
- New public names are exported from `src/spectral_trust/__init__.py` and
  listed in `__all__`.
- Speed or accuracy figures quoted in docstrings, the README or the
  changelog come from a script in `benchmarks/` and its committed results.
- The README figures are generated by `docs/make_assets.py`; change the
  script and regenerate the files rather than editing images by hand.

## Proposing a change

1. For anything larger than a small fix, open an issue first to agree on
   the approach.
2. Create a branch from `main` and keep commits small, one logical change
   each, with a message that says what changed and why.
3. Run the full test suite.
4. Add an entry to `CHANGELOG.md`. Mark any change that alters results for
   existing callers with *(behaviour change)* and say how to get the old
   behaviour back.
5. Open a pull request into `main` describing the change and how you tested
   it.

Contributions are accepted under the project's license, Apache-2.0.
Everyone taking part is expected to follow the
[code of conduct](CODE_OF_CONDUCT.md).
